# ALDC — source of the `bc-dev` Claude Code plugin

DSC Group's fork of
[`javiarmesto/AL-Development-Collection-for-GitHub-Copilot`](https://github.com/javiarmesto/AL-Development-Collection-for-GitHub-Copilot),
carrying **only** the Claude Code plugin: agents, skills, commands and always-on rules for
Business Central AL development.

```
claude-plugin/  ──GitHub Action──▶  dscgroup-bc-nav-agentic-dev / plugins/bc-dev  ──▶  users
```

## Install (as a user)

The plugin is published through the DSC marketplace, not from this repository:

```
/plugin marketplace add DSC-Group-Srl/dscgroup-bc-nav-agentic-dev
/plugin install bc-dev
```

Then, in an AL project, run `/al-initialize` once: it copies the always-on rule templates
into `.claude/rules/` so they persist and stay editable per project.

## What this fork deliberately does not carry

Upstream also ships a **GitHub Copilot / VS Code** product built from root-level `agents/`,
`skills/`, `instructions/` and `prompts/` trees, packaged as a VSIX, an npm package and an
mkdocs site. That chain has been removed here.

DSC uses Claude Code only and never publishes this fork upstream, so the second copy earned
nothing and cost something real: the two trees had drifted into contradicting each other on
indentation, `TryFunction` scope and the name of the test assert codeunit, and whichever
artifact happened to load won. The weekly upstream sync is now path-filtered to
`claude-plugin/**` and replays upstream's commits as patches, so their work on the plugin
still reaches us while the deleted chain stays deleted.

The full reasoning, including the BCQuality review-to-implementation analysis that prompted
it, is in [`.github/plans/bcquality-proactive-integration.md`](.github/plans/bcquality-proactive-integration.md).

## Working in this repository

Read [`CLAUDE.md`](CLAUDE.md) first — it has the layout, the editing rules and the routing
table. The short version:

- edit `claude-plugin/`, never `.claude/` (generated by `scripts/sync-claude-workspace.js`)
- a rule lives in exactly one place: `claude-plugin/rules-templates/`
- where BCQuality already has a knowledge file, defer to it rather than restating it

## Automation

| Workflow | When | What |
|---|---|---|
| `sync-upstream.yml` | Mon 04:00 UTC | replays upstream commits touching `claude-plugin/**` |
| `bcquality-pin-bump.yml` | Mon 06:00 UTC | PR when a newer BCQuality release lands, listing what changed in the corpus |
| `bcquality-evidence.yaml` | manual | checks every citation in a persisted review resolves inside the pinned BCQuality clone |

The marketplace mirror (`plugins/bc-dev`) is synced daily at 05:00 UTC by a workflow in the
marketplace repository.
